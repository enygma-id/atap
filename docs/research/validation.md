# Validation Plan

Validation should cover:

## Geometry

- valid Polygon/MultiPolygon;
- topology;
- expected holes;
- CRS correctness.

## Vertical Consistency

Check invariants such as:

```text
part_height_m =
top_height_agl_m - base_height_agl_m
```

and:

```text
base_elevation_m =
ground_elevation_m + base_height_agl_m
```

## Hierarchy

- valid parent IDs;
- no orphan parts;
- consistent object grouping.

## Reference Comparison

Compare with:

- higher-fidelity mesh;
- photogrammetry;
- point cloud where available;
- manual interpretation;
- known measurements where available.

## Sensitivity

Test multiple building typologies, terrain conditions, and parameter settings.

## Performance

Measure runtime, memory, raster-resolution sensitivity, and building-count
scaling.

A method should not replace the stable baseline because one building looks
better. Improvements should be evaluated across representative cases.

## Engine 0.2.0 reference validation

Four synthetic cases are frozen under `tests/golden/`: default stepped masses, stepped masses with eight classes and regularization, a courtyard case, and a 260-building benchmark. Canonical comparison excludes run timing and execution settings.

Acceptance tests cover mandatory DTM failure, DSM-grid resolution, vertical equations, hierarchy, large-hole preservation, deterministic workers, source IDs, output schema, and atomic writes. Browser tests cover terrain placement, grouping, immutable canonical data, hierarchy, uploads/reuse, queueing, cancellation, and online/offline assets.

Synthetic fixtures are generated by `tools/make_synthetic.py`. No client data is part of the validation set.
